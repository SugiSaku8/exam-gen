
# 定理カタログ基盤の取り込み（2026-10）

`docs/theorem-foundation/` と `js/theorem-catalog.js` は、提供された `proof-theorem-catalog-foundation` リポジトリを分析し、設計資料と定理IDカタログを参照用に取り込んだものです。

今回、生成器本体に加えた変更：
- 問題生成後に `js/proof_audit.js` を実行し、証明ステップと定理カタログの対応候補を記録する。
- 座標モデルに対して点ID・有限座標などの構造検査を行う。
- 結果は `validation.theorem_audit` に記録し、開発者コンソールにも `AUDIT` ログを出す。
- 監査レポートには `catalogued-candidate` / `needs-review` を付ける。ただし文面からの候補推定なので、数学的な証明の正しさを保証するものではない。未対応ステップを「正しい」と扱わず、レビュー対象として残す。

重要な制約：
- 定理カタログの型付き前提・結論を、生成器のすべての証明に対して実行する汎用推論器はまだ接続されていない。
- 2024〜2026型の現行生成は、原問題の座標構造を回転・拡大縮小する方式が中心であり、点配置や条件を自由に再構成する完全な構造生成ではない。
- したがって監査結果は「生成物の構造と定理候補の追跡性を改善する基盤」であり、全数学条件の独立検証済みという意味ではない。

将来の実装順：
1. 証明ステップを文字列ではなく、`statement` / `reason` / `theorem_id` / `premise_ids` の型付きデータで生成する。
2. 定理カタログの型付き前提・結論を実行するマッチャーを作る。
3. 点の順序・半直線・弧の選択を明示する幾何関係モデルと接続する。
4. 定理ごとに正例・負例テストを増やし、条件不足時に誤推論しないことを確認する。
5. 生成した図形の条件・証明・数値答案を独立した検証器で再検査する。
