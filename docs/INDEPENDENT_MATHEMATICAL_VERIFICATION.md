# 独立数学検証と proof-first 生成契約

## 方針

生成器が出した `validation` フラグを検証器が信用することは禁止する。検証器は完成した問題データから独立に条件・座標・証明列・解答を読み直す。未対応の命題は「正しい」と推定せず、未検証として残す。

目標とする順序は **解答の証明計画 → 必要条件の抽出 → 条件を満たす図形の構成 → 問題文生成 → 独立検証**。`generateFromProofFirstPlan(plan, constructProblem)` は新規・移行済みテンプレート向けの厳格な入口で、証明計画の各結論を先行する条件・事実から定理エンジンで導けた場合だけ構築コールバックを呼ぶ。`buildProofFirstSpecification(problem)` は既存テンプレートを監査し、証明目標、証明ステップ、証明グラフ・導出事実が参照する条件ID、追問の答えをまとめる。`ready_for_geometry_construction` が false のときは、参照条件の不足や証明目標・ステップの欠落がある。**既存の2014〜2017・2024〜2026年度テンプレートは互換性のため、現時点では生成後の監査を行う移行途中の状態**であり、すべてが厳格な proof-first 構築関数へ移行済みという意味ではない。

## 検証レイヤー

1. **幾何**: シリアライズ済み座標から円周・平行・等長・角度・交点・非退化性・追問の数値答えを再計算する。2014型はGeometryModel専用検査器を使う。
2. **証明スキーマ**: 2014〜2017・2024〜2026の7テンプレートに対し、レビュー済みの年度別推論スキーマを事前検証し、必須条件・証明目標・規則ID・依存順序を照合する。汎用規則は前提の型と規則出力型を検査し、テンプレート固有の複合規則は明示的な信頼済み規則として登録する。
3. **導出結論の独立数値検査**: 証明スキーマの各角度等式・辺長等式・平行・直角・相似・合同・平行四辺形を、保存された座標から再計算する。1つでも反証された場合は不合格。座標不足は未検証とする。
4. **依存関係**: 条件ID・導出事実ID・証明グラフの参照先、導出順序を検査する。
5. **解答整合性**: 証明目標・ステップ・追問の答えが問題データと矛盾しないかを検査する。

## 状態の意味

- `verified`: 登録済み年度別証明スキーマ、各導出結論の独立数値検査、幾何、依存関係、解答整合性がすべて成功した。これは登録済みテンプレート範囲内の検証であり、任意の未知の幾何命題を証明できる汎用定理証明器を意味しない。
- `partial`: 直ちに反証する矛盾はないが、定理体系で未証明の証明ステップなどが残っている。
- `failed`: 座標の矛盾、答えの不一致、依存関係の破綻などを検出した。生成パイプラインはこの問題を返さず再試行する。
- `not-verifiable`: 独立検証に必要なデータや証明構造が足りない。

`partial` は数学的正しさの保証ではない。自然文から抽出した補助的な `derived_facts` は、年度別証明スキーマとは別に監査し、未対応の事実は未証明として残す。年度別の複合規則は信頼済みのレビュー対象であり、新しいテンプレートを追加する際は同様のスキーマ作成・負例テスト・座標独立検査が必要である。

## 公開API

- `createProofFirstConstructionPlan(templateId)` — 生成前に年度別証明計画と定理規則を検証
- `verifyFormalProofCertificate(problem)` — 必須条件、規則、依存順序、目標を照合
- `auditFormalDerivationNumerically(problem)` — 証明スキーマの各結論を座標から独立再計算
- `buildProofFirstSpecification(problem)` — 証明を起点にした構築契約を生成
- `verifyProblemMathematics(problem)` — 全レイヤーの監査結果を返す
- `assertMathematicallyVerified(problem)` — `verified` 以外を例外として扱う厳格モード

問題生成時のレポートは `problem.validation.independent_math_audit` に保存され、UI上の「数学検証」バッジにも反映される。
